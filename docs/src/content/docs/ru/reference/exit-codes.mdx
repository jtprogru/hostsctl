## Как этим пользоваться

В автоматизации важно отличать `3` от `4`: сломанный конфиг требует человека, нехватка
прав — `sudo`.

```bash
#!/usr/bin/env bash
set -uo pipefail

hostsctl check
case $? in
  0) ;;
  3) echo "конфиг сломан, повторять бессмысленно" >&2; exit 1 ;;
  *) echo "неожиданный отказ" >&2; exit 1 ;;
esac

sudo hostsctl apply -y
```

Ошибки идут в stderr, обычный вывод в stdout, поэтому `hostsctl list | head` работает как
ожидается — включая поведение при `SIGPIPE`, которое Rust по умолчанию подавляет, а
hostsctl возвращает как у обычной unix-утилиты.
